# 自动剪辑：AI 高光切片方案（实现规格）

> 状态：已实现并完成基准验证（第 21 期 c88l8daXiv4）
> 脚本：`scripts/auto_clip.py`
> 关联：`docs/episodes/ep21-dylan-patel-datacenter-2026.md`

---

## 1. 目标与边界

输入一期**双语 SRT**（原语种在上、简体中文在下）与原片 MKV，自动完成：

```
双语 SRT → 防御性校验 → 真实时间滑动窗口 → 本地模型提候选
        → 全局确定性过滤/去重/配额 → 字幕钳位 + FFmpeg/QSV 切片
        → ffprobe 自动验收 → 合规 MP4（仅通过者进入 final/）
```

人工只做最终抽检：画面黑帧、音画同步、字幕烧录正确性、语义连贯。日常运行不做中间决策。

**不做的事**：不做片头导读卡（第一阶段默认关闭）；不改动原片；不生成无字幕版本；不下载任何在线资源。

## 2. 硬性约束

1. **最小依赖**：只用标准库 + 已有 `requests` + llama-server + 系统 `ffmpeg/ffprobe`。不引入 LangChain、向量库、Embedding、任务队列、ffmpeg-python。
2. **确定性优先**：模型只提语义候选（两个 cue ID + 标题 + 摘要）。时间、归属、重叠、时长、过滤、配额、验收全部由 Python 计算并强制。
3. **物理时间轴**：内部统一**整数毫秒**；窗口、切片、重叠、门禁都锚定真实时间戳。
4. **失败分级**：`SUCCESS / PARTIAL / NO_CANDIDATES / FAILED / ANALYSIS_FAILED` 严格区分，模型故障不得伪装成“无高光”。
5. **人工仅最终验收**。

## 3. 现有能力盘点与复用决策

| 能力 | 现有实现 | 决策 |
|---|---|---|
| 双语 SRT 解析 | `build_subs.parse_srt()`：返回 float 秒、自动丢弃解析失败的块、不区分上下行 | **不复用解析器**：新增严格解析 `parse_bilingual_srt()`（整数毫秒、逐块报错、保留原文/中文两行）。原因：现有解析器静默丢块，无法满足“损坏必须 FAILED” |
| ASS 生成 | `build_subs.write_ass()`：`MarginV`、中文 `_wrap_cjk` 硬断行、`\N` 转义 | **复用**，`top_only=False, font="Microsoft YaHei"` |
| SRT 写出 | `build_subs.write_srt()` / `fmt_srt()` | **复用** |
| 模型调用 | `translate_local.py` 的 `/v1/chat/completions` 方式 | 复用调用方式（OpenAI 兼容、低温度、超时、重试） |
| 编码 | README 已有 `h264_qsv -global_quality:v 19 -preset slow` | **复用**；音频按本方案改为 AAC（MP4 容器） |

**不引入 `pysubs2`**：严格解析器不足 80 行，且必须携带“块级错误位置 + 上下行分离”语义；引入新依赖只增加环境面，不增加能力。该决定已固化在本文档与脚本中。

## 4. 配置参数（默认值）

| 参数 | 默认 | 说明 |
|---|---|---|
| `window_ms` | 660000（11:00） | 单窗口长度 |
| `overlap_ms` | 210000（3:30） | 相邻窗口重叠 |
| `step_ms` | 450000（7:30） | = window − overlap |
| `min_clip_ms` | 180000（3:00） | 切片最短（硬门禁） |
| `max_clip_ms` | 480000（8:00） | 切片最长（硬门禁） |
| `prefer_min_ms` / `prefer_max_ms` | 240000 / 360000（4–6 分钟） | 去重时的优先区间 |
| `dup_overlap_ratio` | 0.4 | 重叠率 > 0.4 判为重复 |
| `max_clips` | 2 | 配额上限（按时间先后） |
| `duration_tolerance_ms` | 1500 | 实测时长容差（初期探索值，后续按样本实测固化） |
| `margin_v` | 100 | 字幕底部留白（PlayRes 1440） |
| `video_codec` / `audio_codec` | h264 / aac | 验收时比对的实际编码 |
| `qsv_quality` | 19 | `-global_quality:v` |
| `audio_bitrate` | 160k | AAC |
| `cfr` | 自动 | 源为 VFR 时加 `-fps_mode cfr -r <r_frame_rate>` |
| `base_url` | http://127.0.0.1:8080 | llama-server |
| `model_timeout_s` | 300 | 单次请求超时 |
| `model_retries` | 2 | 传输/JSON/字段错误重试次数 |

## 5. 模块规格

### 模块 1：输入解析与防御性校验

- 逐块解析：可选编号行 → 时间戳行 → 文本行（第 1 行为原语种，其余为中文）。
- 内部 ID：**1 起始的顺序索引**，与 SRT 原编号解耦；保留块序号便于追溯。
- 任一项失败 → `FAILED`：
  - 无法识别时间戳 / 空的文本块；
  - 任一条 `start >= end`；
  - 起始时间非单调非递减；
  - 文本为空或只剩控制字符。
- 输出：`Cue(id, start_ms, end_ms, top, bottom)` 有序列表 + `errors[]`。

### 模块 2：真实时间滑动窗口

- 窗口 `[start, start+window_ms)`，步长 `step = window − overlap`；最后一个窗口右边界钳到 `last_cue.end`。
- 剩余可用跨度 `< min_clip_ms` 的尾窗**不单独生成**（已被前窗覆盖），避免无意义短窗。
- 归属：`cue.start < win_end and cue.end > win_start`（有交集即纳入），保留全局 ID。
- 记录每窗的 `cue_ids`、`min_id`、`max_id`。

### 模块 3：单窗口模型推理

- 仅发送本窗口的 cue（ID + 起止时间 + 原语种文本），Prompt 明示合法 ID 范围与时长门禁。
- 严格返回一个 JSON 对象：`start_cue_id`, `end_cue_id`, `title`, `summary`。
- 失败处理：
  - HTTP 非 200 / 超时 / JSON 解析失败 / 缺字段 / ID 非整数 → 记录 `attempts[]`，重试；
  - 重试耗尽 → 本窗口 `FAILED`，继续后续窗口；
  - `start/end` 必须属于本窗口且 `end >= start`，否则候选判废（记录原因）。
- **时间不由模型给出**：候选时间恒取 `start_cue.start → end_cue.end`。

### 模块 4：全局过滤、去重、配额

对每个原始候选依次执行，任一步淘汰都写入 `removed[]`（含原因）：

1. **归属校验**：ID 必须在该候选所属窗口的 `cue_ids` 中。
2. **物理时长门禁**：`end_ms − start_ms ∈ [min_clip_ms, max_clip_ms]`。
3. **重叠去重**：`R = overlap / min(durA, durB)`；`R > 0.4` 判重。
   - 排序键（确定性）：`(0 若时长在 prefer 区间, 1 否则, |dur − 300000|, start_ms, start_id)`；
   - 按排序贪心保留，后者若与任一保留者 `R > 0.4` 即淘汰，记录 `duplicate_of`。
4. **配额**：去重后按 `start_ms` 升序，最多保留 `max_clips` 个；不足不补、不强行出片。

### 模块 5：字幕钳位 + 渲染

钳位（整数毫秒）：

```
new_start = max(0, cue.start - clip_start)
new_end   = min(clip_duration, cue.end - clip_start)
仅保留 new_start < new_end
仅处理与 [clip_start, clip_start+duration) 有交集的 cue
```

- `-ss <clip_start/1000> -i <input> -t <duration/1000>`，输入 seek 的实际起点与钳位用的 `clip_start` **完全同源**。
- 视频 `h264_qsv -global_quality:v 19 -preset slow`；音频 `aac -b:a 160k`；`-movflags +faststart`；`-map 0:v:0 -map 0:a:0`。
- 源为 VFR（`r_frame_rate != avg_frame_rate` 或分数帧率）时加 `-fps_mode cfr -r <r_frame_rate>`，避免重复 DTS。
- 路径安全：subprocess 参数列表（无 shell）；ASS 滤镜路径优先相对 `ROOT` 的 POSIX 路径；绝对路径时 `\`→`/`、`:`→`\:`。
- 先写 `work/clip-NN.tmp.mp4`，验收通过后再原子移动到 `final/`，避免半成品。
- 片头导读卡：关闭。

### 模块 6：自动媒体验收（ffprobe）

逐项检查并写入 `acceptance.checks[]`：

1. 文件存在、大小 > 0、可解析；
2. 同时存在 video + audio 流；
3. `codec_name` 与配置一致（h264 / aac）；
4. 除 video + audio 外无额外字幕/数据轨（防止章节文本轨等杂物混入）；
5. `|format.duration − 目标时长| ≤ duration_tolerance_ms`；
6. 字幕边界：钳位后所有 `new_start ≥ 0` 且 `new_end ≤ duration`。

任一项失败 → 移入 `quarantine/`，同名 `.failed.json` 记录原因；**绝不进入 `final/`**。

## 6. 状态机

判定顺序（自上而下，第一条命中即终态）：

| # | 条件 | 状态 |
|---|---|---|
| 1 | SRT 校验失败 / 源视频缺失 / ffmpeg 不可用 | `FAILED` |
| 2 | 所有窗口均失败 | `ANALYSIS_FAILED` |
| 3 | 部分窗口失败 且 无任何有效候选 | `ANALYSIS_FAILED`（备注“分析不完整”，禁止落成 NO_CANDIDATES） |
| 4 | 部分窗口失败 且 有候选但渲染/验收任一失败 | `FAILED` |
| 5 | 部分窗口失败 且 至少一个切片通过验收 | `PARTIAL`（`analysis_complete=false`） |
| 6 | 全部窗口成功 且 无有效候选（含全部被门禁/去重淘汰） | `NO_CANDIDATES` |
| 7 | 全部窗口成功 且 渲染/验收任一失败 | `FAILED` |
| 8 | 全部窗口成功 且 所有切片通过验收 | `SUCCESS` |

- 状态、原因、`analysis_complete` 同时写入日志与 `result.json`。
- `--analyze-only` 只做模块 1–4，输出 `analysis.json`，分析级状态：`ANALYSIS_OK / ANALYSIS_PARTIAL / ANALYSIS_FAILED / NO_CANDIDATES`。

## 9. 模型 Prompt（模板要点）

- 系统：资深科技视频剪辑，只输出 JSON。
- 用户：
  - 合法 ID 范围 `[min_id, max_id]`，并强调“只可使用下列 ID”；
  - 每行格式 `[ID] HH:MM:SS.mmm–HH:MM:SS.mmm | 原语种文本`；
  - 给出本窗口字幕条数与平均每条时长，换算成“180–480 秒约等于多少条字幕”，帮助模型遵守时长门禁；
  - 规则：时长 180–480s（优先 240–360s，低于 180s 一律无效）、语义完整、可独立成片、不从句子中间开始/结束、优先完整话题段；
  - 输出唯一 JSON 对象：`{"start_cue_id": int, "end_cue_id": int, "title": "≤24字", "summary": "一句话"}`；
  - 禁止输出时间、禁止 Markdown 代码块、禁止解释。
- 调用：`temperature=0.1`、`max_tokens=500`、`response_format={"type":"json_object"}`（服务端不支持时自动降级）、超时 300s。
- 实测：加入“约需多少条字幕”的换算提示后，同窗口的三次候选由 1 条有效提升到 3 条全部落在时长门禁内。

对 `final/` 内每个 MP4 抽检：

- 开头 0–3s、中间、结尾：无黑帧、无花屏、无上一片段残帧；

### 已知问题与后续

1. **章节文本轨**：FFmpeg 会把源 MKV 的章节重映射到 MP4，并生成一条 `bin_data` 文本轨；
   已加 `-map_chapters -1` 关闭，复渲后输出仅 video + audio。
2. **时长效验容差**：三条样本偏差 +23 / +24 / +41 ms，远小于默认 1500 ms；
   积累更多样本后可收紧到 ±500 ms。
3. **模型合规率**：加入“约需多少条字幕”的换算提示后，3 个候选全部落入 180–480s；
   仍需在更多期数上统计，必要时把提示中的条数换算改为按窗口实际中位语速计算。
4. **合集为何重取流**：单切片已烧录字幕，直接拼接再烧合并字幕会叠字；因此合集按同一
   源区间重新取流并只烧一次。代价是需要源片可访问（`merge_highlights.py` 会拒绝缺失源片）。
