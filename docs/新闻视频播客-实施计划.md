# 新闻视频播客 · 实施计划（YouTube 英文口播）

> 2026-11-12 立项。目标是"证据型新闻评论"：多家媒体报道 + 官方材料 + 你的判断，
> 英文口播、16:9、8–15 分钟，周更 1–2 期。不是新闻搬运，也不是高光切片。
>
> 仓库根 `<repo-root>`；下载/成片数据根 `$NEWS_DATA_ROOT`。代码在 `news/`；媒体产出在 `NEWS_OUTPUT_ROOT`（默认 `<repo-root>/output`），**不进 Git**。

## 1. 结论与边界

| 项 | 决定 |
|---|---|
| 平台 | YouTube（16:9，1920×1080，30 fps） |
| 语言 | 英文画面 + 英文旁白；中文字幕可选（英上中下） |
| 时效 | 允许晚 1 天–1 周；周更，不做突发快讯 |
| 选题 | AI / 科技 / 产业 / 商业；不碰时政、关税、制裁、地缘冲突 |
| 音频 | 新闻类不用 BGM；旁白 + 必要原声 |
| 证据 | 每个事实段必须能回到 `evidence_id`；截图/片段标来源与日期 |
| 配图 | 事实用截图/官方图表；FLUX 只做"插图"，必须标注 illustration，不能当证据 |
| 产出 | 代码、契约、测试、文档可进远程；视频/音频/截图/时间轴/配音不进远程 |

## 2. 三个项目的分工

```text
Opportunity Radar（已有，只读使用）
  FreshRSS → 事件/证据/主张 → 日报/周报
        │  news or-export：只读导出 story pack（不改 OR 评分与门禁）
        ▼
YouTube-B / news（本次新建）
  选题 → story pack → 英文结构/口播稿 → TTS → 截图/配图 → 时间轴 → 渲染 → QC
        │  复用：yt-dlp、faster-whisper、ASS、QSV、验收
        ▼
Local-Drama-Studio（只借生成能力）
  ComfyUI 8188 + FLUX.3：编辑插图 / 风格包 / 参考板
  VoxCPM2 50000：英文参考音与逐句合成（与 CW 共用同一运行时）
```

CourseWorkspace 只借约定：英文旁白、英上中下字幕、新闻不用 BGM、TTS/LLM 串行。
不把 NewsStudio 塞进 CW，也不在 CW 里重复做一套采集与渲染。

## 3. 数据契约

### 3.1 Story pack（Opportunity Radar 导出）

```json
{
  "schema_version": 1,
  "story_id": "evt-...",
  "title": "Headline",
  "event_key": "https://...",
  "first_seen_at": "...",
  "last_seen_at": "...",
  "sources": [
    {"source_id": "s1", "publisher": "Publisher", "title": "...",
     "url": "https://...", "published_at": "...", "rights_status": "approved"}
  ],
  "evidence": [
    {"evidence_id": "e1", "source_id": "s1", "quote": "verbatim excerpt",
     "locator": {"field": "body", "start": 120, "length": 64},
     "verification_state": "unverified", "source_family": "..."}
  ],
  "claims": [
    {"claim_id": "c1", "text": "...", "quote": "...",
     "verification_state": "unverified", "evidence_ids": ["e1"]}
  ],
  "coverage": [
    {"publisher": "...", "headline": "...", "url": "...", "published_at": "..."}
  ],
  "metadata": {"backend": "opportunity_radar", "publisher_count": 2, ...}
}
```

注意：`publisher_count` 不是"独立佐证"；同一集团下的多个博客仍是一个来源族。
是否需要交叉核验，以 OR 的 `source_family / independence / syndication_group` 为准。

### 3.2 Plan（节目结构 + 口播稿）

```json
{
  "schema_version": 1,
  "episode_id": "2026-11-12-slug",
  "title": "...",
  "story_pack": "story-pack.json",
  "fps": 30, "width": 1920, "height": 1080,
  "segments": [
    {"id": "S01", "type": "source_card", "duration_ms": 8000,
     "title": "...", "subtitle": "date · publishers",
     "sources": ["s1"], "narration_text_en": "..."},
    {"id": "S02", "type": "screenshot", "duration_ms": 12000,
     "image": "assets/shot-01.png", "evidence_refs": ["e1"],
     "narration_text_en": "...", "motion": "zoom-in"},
    {"id": "S03", "type": "illustration", "duration_ms": 10000,
     "image": "assets/illu-01.png", "narration_text_en": "..."},
    {"id": "S04", "type": "clip", "duration_ms": 9000,
     "video": "assets/clip.mp4", "video_in_ms": 123000,
     "use_source_audio": false, "narration_text_en": "..."}
  ]
}
```

类型：`source_card / screenshot / illustration / chart / clip / quote`。
`narration_text_en` 必须是英文；出现 CJK 直接报错。时长按 140 wpm 估算，不足会报错。

### 3.3 Timeline（由 plan + 实际 WAV 时长生成）

```json
{
  "schema_version": 1,
  "episode_id": "...", "fps": 30, "width": 1920, "height": 1080,
  "total_ms": 600000,
  "segments": [{"id": "S01", "start_ms": 0, "end_ms": 8000,
                "duration_ms": 8000, "narration_wav": "voice/S01.wav", ...}],
  "cues": [{"start_ms": 120, "end_ms": 4200, "text_en": "...", "text_zh": ""}]
}
```

旁白 WAV 的长短是时间轴权威：比计划时长更长时，段自动延长（记录 warning）；
字幕按句切分并落到旁白实际时长内。`source_card` / `quote` 若没有 `image`，渲染时会用 Chrome 自动生成卡片。

## 4. 已落地的代码（2026-11-12）

```text
news/
├── schemas.py        # Source/Evidence/Claim/StoryPack/Segment/Plan/Timeline + 校验
├── storypack.py      # 读取与摘要
├── or_export.py      # 只读查询 OR SQLite，导出 story pack；列出候选事件
├── plan.py           # 从 pack 起草 plan；计划校验与统计
├── timeline.py       # 实际 WAV 时长 → 毫秒时间轴 + 字幕 cue
├── subs.py           # ASS/SRT：英上中下，字幕安全区
├── capture.py        # headless Chrome 截图；来源卡/引用卡 HTML → PNG
├── illustrate.py     # ComfyUI/FLUX.3 客户端（模板占位符 → 提交 → 下载）
├── tts.py            # VoxCPM2 /tts 客户端；逐段英文旁白；缓存与 manifest
├── render.py         # 分段渲染 + concat + 混音 + 烧字幕 + ffprobe 验收
└── cli.py            # python -m news ...
```

命令：

```powershell
uv run python -m news or-events --db "<OR_DB>" --min-sources 2
uv run python -m news or-export --db "<OR_DB>" --event evt-... `
  --sources-csv "<OR>/config/sources.local.csv" --out "episodes/2026-11-12-slug/story-pack.json"
uv run python -m news draft --pack ".../story-pack.json" --episode 2026-11-12-slug
uv run python -m news validate --plan ".../plan.json" --strict-files
uv run python -m news narrate --plan ".../plan.json"        # 需先启动 VoxCPM 50000
uv run python -m news timeline --plan ".../plan.json"
uv run python -m news card --plan ".../plan.json" --segment S01 --out ".../assets/card.png"
uv run python -m news capture --url "<URL>" --out ".../assets/shot-01.png"
uv run python -m news capture-pack --pack ".../story-pack.json" --episode 2026-11-12-slug --limit 3
uv run python -m news illustrate --prompt "<...>" --out ".../assets/illu-01.png"
uv run python -m news render --timeline ".../timeline.json" --out ".../out/episode.mp4"
uv run python -m news demo --out "<episode>/out/demo.mp4"
```

## 6. 分阶段计划

### M0 选题与资料包（已完成骨架）

- OR `or-events` 选事件；`or-export` 导出 story pack。
- 人工确认：至少 2 个来源族、允许的题材、素材授权。
- 验收：pack 通过 schema；每条 evidence 有 source_id 与 locator。

### M1 一条 8–15 分钟样片（下一步，约 5–8 人日）

- 写英文口播稿（Claude Code 起草 + 人工改写）。
- 截图 3–5 张，配 1–2 张 FLUX 插图；卡片用 Chrome 渲染。
- VoxCPM2 逐段合成（后台，约 2–2.5 小时/期）。
- 生成 timeline，渲染 1080p，抽帧验收。
- 验收：时长、音轨、字幕安全区、每条事实有 evidence、来源清单齐全。

### M2 周更流水线（约 8–12 人日）

- `or-events` 增加周窗口（7 天）与"覆盖墙"候选。
- 截图升级：Playwright 整页/元素截图；付费墙只截公开可见部分。
- 渲染升级：片段插入、来源角标、转场、响度、章节。
- YouTube 包装：标题、描述、章节、1280×720 封面。
- 验收：连续 2 期在 6 小时内完成（不含人工写稿）。

### M3 稳定与扩展（可选）

- RSS 自动入队、Shorts、上传 API（OAuth）。
- Remotion 作为复杂动效渲染器（通过 timeline JSON 薄适配）。
- 多语言字幕；A/B 封面。

## 7. 成本

### 开发（单人 + AI 辅助）

| 阶段 | 人日 |
|---|---:|
| M0 骨架（已完成） | 2–3 |
| M1 首期样片 | 5–8 |
| M2 周更流水线 | 8–12 |
| M3 扩展 | 10–20 |
| **到稳定周更** | **15–23** |

### 每期运行

| 环节 | 时间 |
|---|---|
| 选题 + 资料包 | 30–60 min |
| 英文稿撰写/改写 | 2–4 h（人工，核心价值） |
| 截图 + 配图 | 20–40 min |
| TTS（12–15 min 旁白） | 2–2.5 h（后台） |
| 渲染 | 1–5 min（libx264 20 s 实测 5.9 s；QSV 更快） |
| 字幕/QC/包装 | 30–60 min |

**注意**：VoxCPM2 RTF ≈ 12.8，15 分钟旁白约 3 小时；周更必须提前一天跑 TTS。默认英文参考音是
`my_voice_en_ref_short.wav` + `Welcome to this lesson. Today, we will look at how the model works.`；
若音色或口音不满意，改用 `my_voice_en_ref_norm.wav` 并把 `prompt_text` 换成同名 `.meta.json` 里的完整 transcript。
8080 LLM、50000 TTS、8188 ComfyUI、QSV 四者串行；ComfyUI 与 TTS 不抢显存，但不要同时跑大任务。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| YouTube reused content / 版权投诉 | 实质评论 + 少量引用 + 来源标注；优先官方材料；视频片段短且被评论覆盖；保留替换素材 |
| 付费墙/抓取条款 | 只截公开可见区域；不绕过登录/robots；OR 来源登记先行 |
| 事实错误 | evidence_id + locator 校验；人工 fact-check 签核 |
| 生成图被当证据 | `illustration` 类型在画面标注 "ILLUSTRATION"；禁止用于事实段 |
| TTS 太慢 | 后台跑、按句缓存、先写完全稿再合成；不要边改边合成 |
| 范围膨胀 | 先静帧+卡片+旁白；片段、Remotion、Shorts 后置 |
| 单一来源误判 | 用 OR 的来源族/转载标记；publisher 数不等于独立佐证 |

## 9. 仓库与远程

- **进远程**：`news/` 代码、schema、测试、本文档、README、`.gitignore`、小型 JSON 夹具。
- **不进远程**：`NEWS_OUTPUT_ROOT`（默认 `<repo-root>/output/`）下所有视频、音频、截图、FLUX 输出、时间轴、配音 manifest；
  `downloads/`、`clips/**/*.mp4`、`clips/**/*.wav` 等媒体继续忽略。
- 默认输出根可用 `NEWS_OUTPUT_ROOT` 覆盖；不要把绝对路径写进跟踪文件。
- 测试：`uv run python -m unittest discover -s scripts -p "test_*.py"`。

## 10. 待定决策

1. 首期选题：Gemini 事件只适合做技术 spike，不适合作为正式第一期；建议选一条
   "多来源 + 有产业影响"的 AI/芯片新闻。
2. 英文稿起草：Claude Code 起草 + 人工改写，还是本地 Qwen 初稿？前者质量更高，
   后者不依赖外部。
3. 是否需要中文字幕：面向 YouTube 全球观众可只做英文；若要兼顾中文受众，再开中文字幕。
4. 是否做封面/缩略图自动生成：可复用 `generate_poster.py` 的 Chrome 截图思路。
5. 是否接 YouTube 上传 API：先手动上传，等周更稳定后再接。
