# 片头语与工程化导读规范

> 状态：2026-10-28 落地，第 21 期（c88l8daXiv4 / Dylan Patel）验证通过
> 脚本：`scripts/generate_intro.py`
> 模板：`assets/templates/intro.html`、`assets/templates/transition.html`
> 关联：`docs/自动剪辑-高光切片方案.md`、`docs/配音方案-CosyVoice.md`

---

## 1. 目标与边界

片头不是“营销预告”，而是**一手公开实录的工程化导读**：交代谁、在哪、何时，
点出本期核心技术矛盾，并声明我们交付了什么（完整推演 + 中英双语 + 现场原声）。

硬边界：

- 全程本地：Qwen（`llama-server` 8080）写文案，CosyVoice（`127.0.0.1:50000`）配音，
  HTML/CSS + 本地 headless Chrome/Edge 截帧，FFmpeg/QSV 合成。
- 禁止 Remotion、moviepy、ffmpeg-python、任何云端视频生成模型、任何新重型库。
- 模板固定，每期只替换文案占位符；动画由确定性 CSS / FFmpeg 控制，零随机性。
- 片头时长硬窗口 **6.0–9.5 秒**（推荐 7–8 秒），**60 fps CFR**（与切片/合集同规格）。
- 输出独立 `clips/<video_id>/intro/intro.mp4`，单独验收后再进入合集。

## 2. 视觉规范（模板 2：Bloomberg / FT / Swiss）

### 2.1 强制风格

采用深色、左对齐、强对比、少装饰的“财经智库 / 工业文档”风格：

| 元素 | 规范 |
|---|---|
| 背景 | `#0b0e13` 纯深灰黑；80px 网格，线宽 1px，透明度 ≤ 0.03；轻微暗角 |
| 高亮色 | `#ff5500`（工程橙）；仅用于 4px 左侧竖条、微型标签、竖线 |
| 主标题 | 104px，字重 800，`line-height 1.12`，左对齐，最大宽 1500px |
| 副标题 | 33px，`#93a0b1`，左侧 2px 橙色竖线，最大宽 1220px |
| 讲者戳 | 20px 等宽字体，`#5e6b7c`，字距 2.8px，大写 |
| 系列标签 | 19px 等宽字体，左上角；右上角为三位期号；顶部/底部 1px 分隔线 |
| 版心 | 左右 120px，上 82px，下 72px；标题块从 y=286px 开始 |
| 禁止 | 紫粉霓虹、粒子、复杂发光描边、弹跳飞入、旋转翻转、居中乱塞、无网格 |

### 2.2 固定模板与占位符

模板：`assets/templates/intro.html`。Python **只做字符串替换**，不生成 HTML 结构。

| 占位符 | 内容 |
|---|---|
| `{{ACCENT}}` | 高亮色，默认 `#ff5500` |
| `{{STATE}}` | `0` = 起始态（竖条收起、标题下移 15px/透明）；`1` = 终态 |
| `{{SERIES}}` | 系列标签，如 `AI 基建 / 第 21 期` |
| `{{INDEX}}` | 三位期号，如 `021` |
| `{{STAMP}}` | 右上角小戳，如 `FIELD RECORD / 2026` |
| `{{EYEBROW}}` / `{{EYEBROW_RIGHT}}` | 标题上方小标签，如 `CONTEXT / CPU / DATACENTER` |
| `{{TITLE}}` | 画面大标题（12–18 字） |
| `{{SUBTITLE}}` | 画面副标题（讲者/机构/年份） |
| `{{SPEAKER}}` | 讲者戳，如 `DYLAN PATEL / SEMIANALYSIS` |
| `{{SOURCE}}` | 左下角来源 |
| `{{STAMP_RIGHT}}` | 右下角标签 |

`render_template()` 会在替换后检查是否仍有 `{{...}}`，有则直接失败。

### 2.3 确定性动效

1. 左侧 4px 竖条自上而下展开（FFmpeg `drawbox` 高度 `0 → ih`，0–550ms）。
2. 标题块由 `translateY(15px)`、`opacity 0` 过渡到 `translateY(0)`、`opacity 1`
   （模板内 `@keyframes block-rise` + `cubic-bezier(.16,1,.3,1)`；截帧用 state 0/1，
   FFmpeg `xfade` 150–700ms 完成交叉）。
3. 之后画面静止，仅保留 0.05%/秒的极轻微 Ken Burns（`zoompan`）。
4. 尾部 250ms 淡出到黑；配音结束后不再有额外包装。

转场卡 `assets/templates/transition.html` 使用同一套色板与字体：大号橙色期号 +
左对齐标题 + 等宽页眉页脚，不再使用旧的青色发光风格。

## 3. 片头语文案规范（5W1H 工程化）

### 3.1 三段式结构

总时长 6.0–9.5 秒。`intro_spoken_text` 必须**恰好 3 句**：

1. **Who + Where + When**：`[讲者/机构]，[年份] [场合] 现场实录。`
2. **What + Why/How**：`他/她拆解了 [核心技术矛盾] 的底层边界/算力账。`
3. **We did**：`中英双语，来看现场原声。`

要求：

- 冷峻、客观、可核查；只写节目里出现的事实，不替受访者下结论。
- 禁止“震撼、颠覆、杀疯、炸裂、王炸、封神、史诗、狂欢、重磅、炸场、逆天、
  天花板、降维打击、彻底、疯狂、爆款、必看、速看、太强、无敌”。
- 禁止“本期视频”“记得点赞”“一定要看到最后”等营销语。
- 不要长定语、不要堆信息；每句 12–16 字，整段 40–48 个汉字（英文人名逐字母计数，
  含标点总量 ≤56 字符）。
  上限下调是实测结论：本地 TTS 对 49 字以上的句子常到 11–13 秒，即使 1.15× atempo 也放不进 9.5 秒。
- `screen_title`：12–18 个汉字（不含空格），冷峻判断或设问，不用感叹号。
- `screen_subtitle`：15–25 个汉字，交代讲者与机构/出处。

### 3.2 输出 JSON

```json
{
  "intro_spoken_text": "Daytona 2026，Dylan Patel 现场实录。他拆解了 CPU 瓶颈的算力账。中英双语，来看原声。",
  "screen_title": "CPU 为何成为 AI 新瓶颈",
  "screen_subtitle": "Dylan Patel · SemiAnalysis，2026"
}
```

保存为 `clips/<id>/intro/copy.json`；`--copy-json` 可复用，`--copy-only` 只预览。

## 4. 音频与时长

- 服务：CosyVoice-300M-SFT @ `127.0.0.1:50000`，片头默认预置音色 **中文男**（SFT 模式，
  不传参考音频）；克隆模式（CosyVoice2 + `my_voice_5s.wav`）保留给配音链路。
  第 21 期 2026-10-29 复测：同一句 raw 9.892 s → atempo 1.15× → 8.605 s，窗口 9071 ms。
- 硬窗口 6.0–9.5 秒；推荐 7–8 秒；**60 fps CFR**；1920×1080 yuv420p。
- lead 200ms + voice + tail 250ms；**计划上限 9440ms**（硬窗口 9500 − 60ms
  编码器余量，实测 AAC/帧打包会让成片比计划长 +21ms）；超限先缩尾到 100ms，
  再对配音做 1.00–1.15× atempo。
- **实测语速**：紧凑中文约 5.2–6.1 字/秒（含英文名/数字会波动）。同一句重复合成
  可能相差 ±10%；长定语/多停顿会显著变慢（实测 54 字曾达 11.9 秒）。
  因此**不以字数为唯一依据，以 TTS 实测时长为准**。
- 超限重写（串行版）：先 atempo（≤1.15×）；仍放不进 9.5 秒时，**先杀掉
  CosyVoice 进程树并冷却 2 秒**，再重开 llama-server 让 Qwen 把口播压缩到
  35–45 字（保持 3 句与 5W1H 信息），杀掉 LLM、冷却 2 秒后再开 CosyVoice
  重新合成；默认最多 2 次（`--max-voice-repairs`）。第 21 期 2026-10-28
  复核运行时走的是 atempo 修复路径，详见第 8 节。
- **音视频等长**：时长先按整帧对齐（`frames = round(duration × 60)`，
  `-frames:v` + 输出 `-t`），音频 `apad` 补到同一时长；成片的
  `|video_duration − audio_duration| ≤ 60 ms`（一个 AAC 帧），不留下悬挂流。
- 音量：归一化到 −20 dBFS 目标，`alimiter=0.95` 防削波。
- 独立 `intro.mp4` 只含配音，便于单独试听；合集阶段由 `assemble_highlights.py`
  在片头下混入切片 1 之前约 9 秒的原片音频（15%），最后 0.4 秒淡出，
  切片 1 以 100% 原声接上。

## 5. 渲染流水线

```text
Qwen 5W1H 文案（JSON）
  → Python 替换 assets/templates/intro.html 占位符
  → headless Chrome/Edge 截取 state 0 / state 1 两张 1920×1080 PNG
  → FFmpeg:
       xfade(state0→state1, offset=150ms, duration=550ms)
       → zoompan 0.05%/s
       → drawbox 4px 橙色竖条（0→1080px，0–550ms）
       → 200ms 淡入 / 250ms 淡出
       → h264_qsv 60fps CFR + aac 48k（音频裁到视频末尾）
  → ffprobe 验收 → clips/<id>/intro/intro.mp4
```

不依赖 Playwright（本机未安装时使用 headless Chrome/Edge 的等价能力）；
无浏览器时回退 FFmpeg drawtext 静态卡（`picture.animation=static`）。
整个过程只新增 `assets/templates/` 两个 HTML 文件，不新增 Python 依赖。

合集阶段：`assemble_highlights.py` 在片头音轨下混入原片前导床（15%，最后 0.4 秒淡出），
再以 100% 原声进入切片 1；`assembly.bed` 记录起止、音量与淡出时长。

**拼接规则**：片头、标题卡与切片必须规格归一化（60fps CFR、1920×1080、yuv420p、
AAC 48k 立体声、统一视频 timescale），然后优先用 **concat demuxer**
（`-f concat -safe 0 -c copy`）拼接；只有无法流拷贝时才重编码。
详见 [`自动剪辑-高光切片方案.md`](自动剪辑-高光切片方案.md) 第 15 节。

### 5.1 与资源调度的关系

片头不再是“一个脚本做完所有事”，而是拆成四个互斥阶段：

1. **LLM**：高光候选（可选）+ 5W1H 文案，结束后 `taskkill /F /T` 杀掉 llama-server；
2. **TTS**：CosyVoice 配音 + 时长审计，结束后杀掉进程树；
3. **PICTURE**：headless Chrome 截两张 PNG，零显存；
4. **MEDIA**：FFmpeg/QSV 合成片头并拼合集，开编前断言无模型进程。

因此 `generate_intro.py --stage all` 与 `run_pipeline.py` 必须通过
`resource_manager` 启停服务；直接假定“服务已经在跑”的用法不再受支持。
完整规则见 [`资源调度-串行生命周期.md`](资源调度-串行生命周期.md)。

## 6. 验收标准

`intro.json` 的 `acceptance.checks` 至少包含：

1. `file_exists` / `probe`
2. `has_video` / `has_audio` / `video_codec=h264` / `audio_codec=aac` / 仅 AV 流
3. `duration_window`：6000–9500ms；`duration_target`：与计划偏差 ≤250ms
4. `resolution=1920×1080`；`fps=60`
4b. `av_duration_equal`：音视频流时长差 ≤60ms；`audio_starts_at_zero`：音轨起点 ≤60ms
5. `keyframes_exist` / `keyframes_distinct`（state 0 与 1 必须不同）
6. `copy_structure`：恰好 3 句、字数合规、无禁用词
7. `voice_audible`：平均音量 > −50dB（共 17 项）

任一失败：写 `intro.rejected.mp4` 与失败原因，不进入 `final/`，不参与合集。
